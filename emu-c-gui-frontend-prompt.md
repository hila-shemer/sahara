# Work order: sahara-gui — the interactive SDL2 front end for emu-c

Branch: `frontend` (worktree of the main repo, full spec access). Read
`emu-common-prompt.md` and `emu-c-prompt.md` first; they govern. This
starts the GUI phase that emu-c-prompt.md reserves for last: the shared
suite is green headless for both emulators, so the phase gate is
satisfied — say so in your opening commit message.

The design below was settled in advance and is **binding**. Do not
relitigate the resolved decisions; where you must invent a reading, the
inventions are already enumerated and each one gets a SPEC-ISSUES.md
entry before merge, per house protocol.

## Why this exists

The determinism contract already defines a live session. PLATFORM-SPEC
§8 (frozen): an interactive GUI session records its inputs as a trace
as it runs; any session is therefore replayable bit-exactly in headless
mode. devspec/trace.md 5.4 gives the one live-mode rule: events may be
applied at any inter-instruction boundary, but the recorded EVENT cycle
must equal the boundary of application.

The front end is therefore a device-event *author* whose output must
survive `sahara-emu --replay` byte-identically. It is designed
backwards from the trace; everything below derives from that.

emu-c is the host (resolved): ~9.6M instr/s, the boundary-injection
API already exists as the replay-tested contract, and emu-c-prompt.md
pre-authorizes SDL2 for exactly this. emu-py stays headless-only per
its own prompt. No emu-py changes of any kind.

## What already exists — do not rebuild it

- **The injection contract.** `SeDev_inject_input` /
  `SeDev_inject_resize` (dev.h) applied by `apply_events` (cpu.c) at
  inter-instruction boundaries, recorded by `SeTrace_event` (trace.c)
  with recomputed drop flags. This is the replay-tested EVENT path
  from the device phase; the front end reuses it wholesale.
- **The run loop seam.** `SeCpu_step` is non-blocking with no hidden
  state; `wfi_wait` (cpu.c) does the jump-to-known-cycle logic; the
  replay feed lives on `SeCpu` (cpu.h) and applies in record order.
- **The tracer.** META (seven keys, catalog order, trace.md 2.3.7),
  levels 0-2, EVENT-before-TRAP per-cycle ordering (T-09).
- **The frozen headless CLI.** `sahara-emu IMAGE [--replay F]
  [--trace F --trace-level N] [--maxcycles N] [--ram BYTES]
  [--check-invtp] [--check-devorder N]` — untouched, byte-for-byte,
  flags and output vocabulary alike.
- **The gates.** `emu-c/build.sh` (encoding check, crosscheck, header
  drift, bazel build+test, image tests, REPLAY=1 conformance suite)
  and `tests/run-tests.sh` (toolchain-owned, never edited here).
- **The NIC stub.** main.c rejects NIC EVENT records loudly
  (SPEC-ISSUES 35). Keep it that way: no live NIC, no NIC EVENTs
  generated by the GUI, no bridging/translator in this milestone —
  the emu-c-prompt.md NIC-bridge paragraph is explicitly deferred.

## Binding decisions

1. **Separate binary, core untouched.** New bazel target `sahara-gui`
   linking the existing `:core`; SDL2 via system headers +
   `linkopts=["-lSDL2"]`, no BCR dep. The SDL TU is a carve-out:
   relaxed copts / `allow_banned=True` (rwc.bzl supports it), excluded
   from the hand-wired audit sh_tests. The core library and the
   headless binary build exactly as today.

2. **One injection path, shared with replay.** The core grows a small
   live-feed queue: `SeCpu_feed(cpu, device, payload, len)` appends an
   `SeEvRec`; the *unchanged* `apply_events` consumes it at the next
   boundary exactly as it consumes replay records — device applies,
   drop flag recomputed, `SeTrace_event` records what was accepted.
   The front end never calls trace or device functions directly, so
   live and replay cannot diverge. (Escape hatch: if the queue
   genuinely cannot fit `apply_events` as-is, extract
   `apply_one_event(dev, idx, payload)` called by both paths — the
   queue remains the mechanism of record.)

3. **Cycle assignment (precise).** A host event polled by SDL is fed
   at the first inter-instruction boundary the loop reaches after the
   poll; its recorded cycle is `cpu->cycle` at that boundary. A polled
   batch feeds at the same cycle in poll order = record order; EVENTs
   precede that cycle's TRAP/EXEC automatically because feeding
   happens before `SeCpu_step` (T-09 preserved). Record what happened,
   never an intention; no event is ever stamped in the past.

4. **Rendering.** SDL2 window + one streaming `SDL_Texture`,
   ARGB8888 (bit-identical to guest XRGB8888 LE; X byte ignored).
   Guest pixels live in SeMem's sparse 64KB pages: v1 blit is a
   page-walking row copy (geometry from `dev->disp_width/height/
   stride`) into a staging buffer — ~1.2 MB/frame, trivial at 60 Hz.
   No contiguity optimization in v1. PRESENT-driven with coalescing:
   a 2-line hook in dev.c sets `dev->present_pending` on the PRESENT
   DEVW; the UI pump (~16 ms tick) uploads+renders iff pending, then
   clears it. No PRESENT, no repaint. `present_pending` is pure
   front-end state, never read headless.

5. **Window: fixed 640x480, non-resizable.** Opens at the reset mode
   (640x480, stride 2560, format 1) — mandatory, since META cannot
   carry a display mode and replay assumes the reset default. Resize
   is deferred to v2; record the v2 recipe in frontend-notes.md
   (coalesce drags; legal geometry at a boundary: STRIDE = 4*W rounded
   up to 16, bounds checked, format 1; through the feed path so it is
   traced; letterbox stale frame per display.md 6.5) and do NOT
   implement it.

6. **Input translation — all outside the models, per input.md.**
   - SDL scancode → HID usage (SDL scancodes are USB page-7 usages);
     filter to the 103-ID subset, silently discard out-of-table keys;
     bit32 press/release.
   - Suppress host auto-repeat (`ev.key.repeat`).
   - Per-key press/release alternation bookkeeping; synthesized
     releases on focus/capture loss (`FOCUS_LOST`) — input.md 2.6 is
     normative.
   - Mouse: absolute position clamped against current display W/H *at
     the injection boundary*; buttons packed; feed only when the
     clamped triple differs from the last generated triple.
   - Capture UX per input.md Appendix A: click-to-capture, hidden
     confined pointer, left Ctrl+Alt releases.

7. **Pacing.** Throttled chunked loop, default 2,000,000 cycles/s
   (`--hz N`, `0` = free-run). Each iteration: `target = C0 +
   (now - t0) * HZ`; step until `cycle >= target` or ~16 ms of wall
   time; poll SDL; translate + feed; blit if pending; sleep to next
   tick. If >100 ms of virtual time behind, slew `t0` forward — no
   catch-up bursts. The wall↔cycle map is a pacing heuristic only: it
   never appears in semantics or the trace. Only this binary reads
   the wall clock.

8. **WFI — the hard case.** Headless `wfi_wait` jumps to the next
   known event/timer cycle and halts on deadlock; live, the next event
   does not exist yet and halting is wrong. Rule: when `wfi_wait`
   finds nothing pending and no reachable armed timer, the core
   returns an **idle/yield** outcome — pc still at the WFI, nothing
   retired, no records emitted — gated by an `SeCpu` flag that is
   unset in headless builds. The front end blocks in
   `SDL_WaitEventTimeout` (timeout = wall time at which cycle_target
   reaches `timecmp` if a timer is armed, else indefinite with a
   housekeeping tick). Host input at wall time t is stamped
   `E = max(wfi_cycle + 1, cycle_target(t))` and fed; on re-entry
   `wfi_wait` sees the pending feed event at E and jumps exactly as
   headless replay would. Trace shape: EXEC(WFI)@C, EVENT@E, TRAP@E —
   the shape SPEC-ISSUES 32 anticipates, byte-identical under replay.
   A truly deadlocked guest idles until window close; live mode never
   takes the WFI-deadlock halt (deadlock is only meaningful when the
   event feed is closed). This invented reading gets a SPEC-ISSUES
   entry.

9. **Recording is mandatory and is the source of truth.** Always
   write a standard trace; default `session-<timestamp>.trc` when
   `--trace` is absent; default level 0 (META+EXEC+TRAP+EVENT — the
   cheapest *legal* level; do not invent an EVENT-only level here,
   propose it in SPEC-ISSUES instead). META via the existing tracer
   with `mode=live`, seven keys in catalog order. On clean exit print
   the exact `sahara-emu --replay` command that reproduces the
   session. Two live sessions can never be byte-identical (human
   timing) — expected and spec-compliant; nobody "fixes" this.

10. **New CLI, old CLI frozen.**
    `sahara-gui IMAGE [--trace OUT.trc] [--trace-level {0,1,2}]
    [--hz N] [--ram BYTES] [--maxcycles N]` plus hidden test-only
    `--script FILE` (fake host-event source + fake clock). Exit paths
    mirror the frozen vocabulary (`HALT r0=...`; window close = clean
    exit 0 after trace finalize + printed replay command). Zero flag
    or output changes on `sahara-emu`.

## Deliverables

1. Core seam patch: `SeCpu_feed` live-feed queue, flag-gated WFI
   yield outcome, `present_pending` hook — all inert headless.
2. `emu-c/gui/`: `sdl_main.c`, `hid_map.c/h`, `blit.c`, plus the
   translation layer factored into an SDL-free TU compiled under full
   rwc doctrine (it is what the unit tests target).
3. `BUILD.bazel` carve-out target (`allow_banned` SDL shim, audit
   exclusion); core library stays pristine.
4. Tests, in an emu-c-owned script `emu-c/run-gui-tests.sh` — never
   under `tests/`:
   - **Core-seam record→replay identity (the keystone).** A driver
     binary (no SDL, links `:core`) feeds scripted sequences through
     `SeCpu_feed` at fabricated boundaries against a small guest,
     records a trace, replays it with `sahara-emu --replay`, and
     byte-compares all post-META records. Variants: events arriving
     during WFI idle (yield/stamp-at-E vs headless-jump equivalence);
     burst >256 kbd events (drop-flag recompute, flags bit0);
     same-cycle multi-event ordering (EVENT-before-TRAP, T-09).
   - **End-to-end scripted-session gate.** `sahara-gui --script
     events.txt` under `SDL_VIDEODRIVER=dummy` runs a canned session
     over a conformance-style image; replay the produced trace with
     `sahara-emu --replay`; require byte identity. This exercises the
     whole live pipeline through the real binary.
   - **Translator unit tests** on the SDL-free TU: scancode→HID
     table incl. out-of-table discard; repeat suppression;
     alternation state machine incl. focus-loss release synthesis;
     mouse clamp + dedup-vs-last-generated; the page-walking row
     copy across 64KB seams and odd strides.
5. `emu-c/gui/demo.s` smoke image (assembled by asm/asm.py: drains
   kbd, plots pixels, PRESENTs) and `emu-c/gui/frontend-notes.md`
   (incl. the two-live-sessions-never-match note and the v2 resize
   recipe).
6. SPEC-ISSUES.md entries: live WFI yield reading; `mode=live` META
   value; default HZ; GUI default trace level; events-only trace
   level proposal.
7. One-line amendment noting the GUI phase started (phase gate
   satisfied: suite green).

## Definition of done

All from the worktree root unless noted; every gate green:

- `emu-c/build.sh` end to end — it must now also build `sahara-gui`
  (its `bazel build //...` picks the new target up), and the REPLAY=1
  conformance leg stays green.
- `./run_tests.sh` (repo root harness; delegates to emu-py's suite)
  green — proves the emu-py leg saw no fallout.
- `emu-c/run-gui-tests.sh` green: seam driver + scripted-session gate
  + translator units, all headless, no real window
  (`SDL_VIDEODRIVER=dummy`).
- **Headless byte-identity** — the frozen binary's behavior is
  unchanged, verified directly, not assumed:

      git worktree add /tmp/sahara-base "$(git merge-base main HEAD)"
      (cd /tmp/sahara-base/emu-c && bazel build //:sahara-emu)
      REPLAY=1 EMU=/tmp/sahara-base/emu-c/bazel-bin/sahara-emu \
          tests/run-tests.sh
      cp -r tests/out /tmp/sahara-base-out
      REPLAY=1 EMU="$PWD/emu-c/bazel-bin/sahara-emu" tests/run-tests.sh
      for f in tests/out/*.a.trc; do
          cmp "$f" "/tmp/sahara-base-out/$(basename "$f")" \
              || { echo "HEADLESS DRIFT: $f"; exit 1; }
      done

  Same suite checkout, both binaries, byte-compared traces. Any DRIFT
  line is a stop-the-line failure.
- The scripted-session gate's produced trace replays through the
  **unmodified** `sahara-emu --replay` invocation printed by the GUI
  on exit, byte-identically at level (T-18 property).
- SPEC-ISSUES entries and the phase amendment committed.

## Scope boundaries

- No edits under `tests/` or `trace-q/` — toolchain-owned. New checks
  live in `emu-c/run-gui-tests.sh`. If a suite bug blocks you, record
  it in SPEC-ISSUES.md and stop rather than patching around it.
- No `sahara-emu` CLI or output changes; core seam changes must be
  dormant headless (feed queue empty, `present_pending` never read,
  yield flag unset).
- No emu-py changes.
- No NIC bridging, translator, or live NIC EVENTs.
- No window resize (v2), no dirty-rect/CAPS extensions, no
  contiguity/performance work beyond the page-walk blit.
- Trace-size pressure is real (level 0 = one EXEC per instruction at
  2 MHz): if fwrite-per-insn drags throughput below ~1 Mips, buffer
  the writes — never hack the format; the real fix is the events-only
  level SPEC-ISSUES proposal.

## Manual smoke checklist (with demo.s, not CI)

- Window opens 640x480; pattern appears on PRESENT; no PRESENT means
  the last frame persists.
- Typing produces visible effect; press+release pairs in the trace;
  held key = one press (no auto-repeat).
- Click captures the mouse (pointer hidden, confined); left Ctrl+Alt
  releases; motion draws.
- Alt-tab away mid-keypress → guest sees a synthesized release
  (verify in the trace).
- Idle guest in WFI wakes on keypress; armed timers fire at sane
  wall-clock moments.
- Close window → trace finalized, replay command printed, and running
  that exact command reproduces the session byte-identically.
